## 项目简介

本项目持续收集、归档、整理并结构化创游世界相关资料，目标是把零散内容整理成一个长期可维护、可搜索、可追溯的中文知识库。

资料库内容包括但不限于：

- 创游世界基础教程
- 脚本系统与积木机制
- 变量、广播、事件、作用域与数据流
- UI 交互、按钮、弹窗、界面设计
- 组件机制、项目结构和系统设计
- 商店、背包、货币、存档、地图、新手引导等项目设计专题
- OCR 识别资料、截图证据、图片编号映射和证据链说明
- 官方教程、视频资料、引擎更新和社区观察
- 维护报告、内容审计、资料状态和后续路线图

这个仓库的目标不是单纯“堆资料”，而是把内容整理成：

> **可导航、可追溯、可检索、可维护、适合玩家学习，也适合 AI 检索的中文资料库。**

## 仓库亮点

- **资料可导航**：通过首页、总导航、新手路线、按问题查资料、分类导航和自动目录降低查找成本。
- **结论可追溯**：重要结论尽量回到截图、OCR、官方内容、专题研究或维护记录。
- **内容可检索**：基于 VitePress 构建文档站，支持结构化阅读和本地搜索。
- **维护可持续**：通过 frontmatter、侧边栏生成脚本、UI 检查脚本、链接修复脚本和内容审计脚本降低长期维护成本。
- **适合 AI 检索**：保留 `llms.txt`、OCR 资料、专题文档、证据等级和结构化入口，方便后续用于 AI / RAG 知识库。
- **开源反馈友好**：提供 GitHub Issue 模板，方便反馈文档错误、失效链接、OCR 修正、资料建议和站点体验问题。

## 当前维护重点

当前资料库主要围绕以下方向继续优化：

1. 提升文档站 UI 美观性、阅读体验和移动端表现。
2. 整理脚本系统、变量、广播、UI、项目设计等重点专题。
3. 清理重复、过期、散落、缺证据或导航不清晰的文档。
4. 补充 OCR 原始资料、证据链、图片编号映射和待验证内容。
5. 优化搜索、SEO、sitemap、robots.txt、缓存策略和 AI 检索友好度。
6. 增强自动化维护脚本，减少手动检查和重复整理成本。

## 本地运行

本项目使用 VitePress 构建文档站，推荐使用 pnpm 管理依赖。

### 安装依赖

```bash
pnpm install
```

### 启动本地开发预览

```bash
pnpm run docs:dev
```

### 仅启动开发服务器

```bash
pnpm run docs:dev:host
```

### 正式构建

```bash
pnpm run docs:build
```

### 预览构建产物

```bash
pnpm run docs:preview
```

构建产物默认输出到：

```txt
docs/.vitepress/dist
```

## 一键部署检查

本项目提供适合 Windows PowerShell / VSCode 终端使用的一键部署检查脚本。

推荐命令：

```bash
pnpm run docs:deploy
```

这个命令会自动完成：

1. 检查当前目录是否为项目根目录。
2. 检查 Node.js 与 pnpm 环境。
3. 生成 VitePress 侧边栏和自动目录。
4. 检查文档 frontmatter。
5. 检查文档站 UI 关键文件。
6. 执行 VitePress 正式构建。
7. 检查构建产物是否生成。

清理旧构建产物后重新检查：

```bash
pnpm run docs:deploy:clean
```

第一次在新电脑上运行，或者依赖可能不完整时：

```bash
pnpm run docs:deploy:full
```

说明：

- 本脚本不会自动 `git commit` 或 `git push`。
- 本项目推荐使用 VSCode Git UI 手动提交和同步。
- 推送到 GitHub 后，Cloudflare Pages 会自动部署线上文档站。
- Cloudflare Pages 的构建输出目录应保持为 `docs/.vitepress/dist`。

## 文档状态与证据等级

为了避免把“推测”写成“确定结论”，本项目会逐步标记文档状态和证据等级。

### 文档状态

| 状态 | 含义 |
|---|---|
| 草稿 | 初步记录，结构和结论仍可能变化 |
| 整理中 | 已开始分类和归纳，但仍需补充 |
| 已整理 | 已完成基础结构整理 |
| 已结构化 | 具备较完整的层级、索引和交叉链接 |
| 待验证 | 包含证据不足或需要复核的内容 |
| 已复核 | 主要来源和结论已完成核对 |

### 证据等级

| 等级 | 名称 | 含义 |
|---|---|---|
| E1 | 原始证据 | 来自截图、界面、OCR、官方内容或原始记录 |
| E2 | 整理证据 | 基于多个原始资料进行整理、分类和归纳 |
| E3 | 研究结论 | 基于已有资料进行人工分析、总结和解释 |
| E4 | 待验证内容 | 暂时缺少足够证据，需要后续继续验证 |

详细说明：

- [资料证据等级说明](https://cysjdocs.azek431.top/元信息/资料证据等级说明)

## 文档元数据规范

新增或整理文档时，建议优先补充 frontmatter：

```yaml
---
title: 文档标题
description: 简要说明这篇文档解决什么问题。
category: 分类名称
tags:
  - 创游世界
  - 脚本
  - 项目设计
status: 整理中
evidence: E3
created: 2026-05-16
updated: 2026-05-16
---
```

推荐字段说明：

| 字段 | 说明 |
|---|---|
| `title` | 文档标题 |
| `description` | 文档摘要，用于搜索、SEO 和 AI 检索 |
| `category` | 所属分类 |
| `tags` | 标签，建议包含主题关键词 |
| `status` | 文档状态 |
| `evidence` | 证据等级 |
| `created` | 写作日期 |
| `updated` | 更新日期 |

## 维护原则

本项目长期遵守以下原则：

1. **不随意删除原始资料**：原始截图、OCR、历史资料优先保留。
2. **不把待验证内容写死**：不确定内容应明确标记“待验证”。
3. **结论尽量有来源**：重要结论尽量关联截图、OCR、官方内容或专题整理。
4. **新增内容要挂入口**：新增高价值文档后，应同步更新导航、索引或阅读路线。
5. **优先改善可读性**：比起盲目增加数量，更重视分类清晰、标题准确、路径好找。
6. **兼顾用户和 AI 检索**：标题、描述、标签、证据等级应尽量清晰稳定。
7. **历史报告先归档再整理**：不直接删除有价值的历史维护记录。
8. **普通用户入口优先清晰**：导航页应避免让用户直接陷入历史报告或维护细节。
