## 多地图项目的关键判断

- `[已确认]` 切换地图时，最容易出问题的是“数据归属不清”。
- `[已确认]` 页面临时状态不等于项目长期状态。
- `[已确认]` 需要跨地图保留的值，应尽量放在更稳定的系统层或存档层。
- `[高可信推断]` 地图越多，越需要在一开始就定义清楚：初始化、退出、恢复、同步这四类流程。

## 推荐关注的四个层次

### 地图层
负责：
- 地图专属对象
- 场景内交互
- 临时事件与局部状态

### 系统层
负责：
- 玩家长期状态
- 跨地图共享数据
- 任务推进与全局规则

### UI 层
负责：
- 页面显示
- 操作入口
- 当前地图所需信息的展示

### 存档层
负责：
- 长期保留的进度
- 跨重进仍需恢复的数据
- 云同步或本地恢复逻辑

## 常见误区

- 误区 1：每进一个地图都重新造一套核心数据。
  - 后果：跨地图同步成本暴涨。
- 误区 2：把页面状态误当成全局状态。
  - 后果：关闭页面或切地图后状态丢失。
- 误区 3：切换地图前后没有统一的初始化和回收逻辑。
  - 后果：残留对象、重复广播、旧数据污染新地图。
