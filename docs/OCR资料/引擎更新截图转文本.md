## 1. Screenshot_20260418_105516.jpg

### 对应版本
4.54.0

### OCR 摘录
```text
Multiplayer UI
In this update, we've completely rebuilt the way the UI runs behind the scenes.
The goal: make UI scripts in multiplayer run just as smoothly as they do in single-player.
In the old version, every player's game would simulate all players' UI logic on their own device.
To keep everyone's UI synchronized, the system had to limit the refresh rate to 20 FPS.
In the new version, each player's device only runs UI logic for their own UI.
This means heavier, more complex UIs can run at full...

【玩家.当前UI】已弃用, 自动替换为更短的【当前UI】。
推荐替代方案是执行“玩家.向当前UI发广播”, UI 收到广播后所有操作都在 UI 里进行。
```

### 人工整理
该图说明 4.54.0 的核心更新之一是“联机 UI 运行机制重构”：
- 旧版本中，每个玩家设备会模拟所有玩家 UI 逻辑。
- 为保持同步，系统刷新率被限制到 20 FPS。
- 新版本改为“每个设备只运行自己 UI 的逻辑”，显著减轻负担。
- 因此更复杂的 UI 在联机中也能更流畅运行。
- 同时 API/脚本层有兼容变更：
  - `玩家.当前UI` 被弃用
  - 改为 `当前UI`
  - 地图脚本不再适合直接操作当前 UI，推荐用“玩家向当前 UI 发广播”来转交 UI 自己处理

### 关键词

- 联机UI
- Multiplayer UI
- UI重构
- 20FPS

脚本变动:

### 人工整理
这张图是 4.52.54 的关键页，解释了联机 UI 优化与“上传并等待”机制：
- 新 UI 逻辑比旧 UI 更高效，因为只运行本人的 UI。
- 旧方案为了同步，需要在所有设备模拟所有 UI，并被限制到 20 FPS。
- UI 中凡是改公共数据（地图、玩家）的脚本，都要上传并等待服务器确认。
- 最佳实践是：UI 只发一次广播，把真正的公共逻辑放到地图里执行。
