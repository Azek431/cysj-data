- 分类：研究报告 / 维护文档 / 质量审查

- 来源类型：全库扫描 + docs 关键文档抽查 + OCR 工程文档复检 + 外部检索补强

- 适合查询：全库哪里有错、哪些问题最影响可信度、下一步先修什么

## 1. 使用说明

本文件只做两件事：
1. 记录当前资料库中已经发现的明确错误、疑似错误、结构性缺陷
2. 给出可落地的修复方向，避免只停留在口头建议

可信度标签统一使用：
- `[已确认]`
- `[高可信推断]`
- `[待验证]`
- `[疑似错误]`

## 3. 结构性优化点

### 3.1 元信息模板执行不完全
- `[已确认]` meta、OCR、索引类文档较多已带头部元信息
- `[已确认]` 但仍有一批专题文档未完全统一为同一模板
- `[高可信推断]` 这会影响 AI 切块检索、批量筛选与版本追踪

### 3.2 可信度标签体系尚未全库落地
- `[已确认]` 元数据规范中已有“证据等级”体系
- `[已确认]` 用户要求的四级可信度标签（已确认 / 高可信推断 / 待验证 / 疑似错误）尚未系统写入全部研究型文档
- `[高可信推断]` 这是当前最影响“研究结论可审计性”的缺口之一

### 3.3 OCR 工程闭环仍未覆盖全部编号
- `[已确认]` OCR 层已有总表、总览、规范、推进清单、映射表
- `[已确认]` 但官方教程与脚本截图仍未做到逐图闭环
- `[高可信推断]` 目前更接近“高价值骨架完整化”，未到“全量编号治理”

### 3.4 总索引强，但按版本/状态/项目场景的子索引还可以更强
- `[已确认]` 总索引已经比较完整
- `[高可信推断]` 如果补出“按版本索引 / 按项目系统索引 / 按可信度索引 / 按研究状态索引”，全库导航会更稳

## 4. 研究内容层优化点

### 4.1 广播、UI、作用域、项目结构已较成熟
- `[已确认]` 这几条主线已有较高质量专题支撑

- `[已确认]` 当前已有不少工程归纳

- `[已确认]` 社区分析文档已经多次声明“不等同于官方定义”
