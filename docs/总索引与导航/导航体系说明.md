# 导航体系说明

这个页面用于说明资料库中不同导航页面的分工，避免多个入口重复承担同一件事。

## 核心导航层级

推荐的导航层级是：

- 首页
- 按问题查资料
- 创游世界知识库总导航
- 分类导航
- 具体文档

## 各入口的职责

| 入口 | 面向谁 | 主要作用 |
|---|---|---|
| 首页 | 所有用户 | 快速了解资料库是什么、能查什么、从哪里开始 |
| 按问题查资料 | 不知道分类的新用户 | 根据问题定位资料入口 |
| 知识库总导航 | 想看全局结构的用户 | 展示资料库主要分类和核心入口 |
| 分类导航 | 已经知道方向的用户 | 进入脚本、项目设计、OCR、维护等具体分类 |
| 自动生成文档目录 | 维护者和重度用户 | 查看当前全部文档结构 |

## 首页应该承担什么？

首页应该解决：

- 这个资料库是什么？
- 我能在这里查什么？
- 新手从哪里开始？
- 脚本、项目设计、OCR、维护入口在哪里？
- 资料可信度如何判断？

首页不应该变成超长目录。

## 按问题查资料应该承担什么？

按问题查资料应该解决：

- 我是新手，不知道看什么
- 我想学脚本
- 我想做项目
- 我想查 OCR
- 我想看维护状态
- 我想判断资料可信度

它面向“不知道分类名”的用户。

## 知识库总导航应该承担什么？

知识库总导航应该解决：

- 资料库有哪些大区？
- 每个大区有什么作用？
- 每个大区推荐先看哪几个文档？
- 如果我想系统浏览全库，该怎么走？

它面向已经愿意系统了解资料库的用户。

## 分类导航应该承担什么？

分类导航不应该重复全站说明，而应该聚焦当前分类。

例如：

- 脚本系统导航：只讲脚本相关入口
- 项目设计导航：只讲项目设计相关入口
- OCR资料导航：只讲 OCR 资料和证据链入口
- 维护与报告导航：只讲维护、报告、状态和规则

## 自动生成目录应该承担什么？

自动生成目录适合：

- 查看全部文档
- 检查文件是否被侧边栏识别
- 维护者确认分类结构
- 重度用户快速跳转

它不是普通用户第一入口。

## 后续维护规则

1. 新增重要文档后，至少挂到一个人工导航页。
2. 普通用户入口优先使用站内链接，而不是仓库路径。
3. 历史报告类文档应保留，但不要作为第一入口。
4. 如果一个导航页越来越长，应拆成“总入口 + 分类入口”。
5. 自动目录只负责兜底，不代替人工导航。
