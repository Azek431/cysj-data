## 4. 创游世界引擎的当前可确认研究结果

基于官方教程、脚本界面截图、更新说明与社区资料交叉分析，目前可以较稳定地归纳出以下系统结构。

### 4.1 对象模型
创游世界至少存在一条相对清晰的结构链：
- 素材：模板 / 资源定义
- 物体：地图中的实例
- 组件：给对象附加能力
- 脚本：在特定上下文中调度行为

这说明创游世界更接近“对象 + 组件 + 事件 + 可视化脚本”的能力模型，而不是单纯的代码环境。

### 4.2 组件体系
从脚本界面和教程资料看，组件体系具有明显分层：
- 通用
- 战斗
- 装置
- 显示
- 交互
- 自定义

这意味着引擎的设计强调“能力装配”，不是把全部逻辑塞给单一对象。

### 4.3 脚本与作用域
从脚本截图可以明确存在多层数据归属：
- 局部变量
- 自身属性
- 地图属性
- 系统属性

这几层不是简单命名差异，而是项目设计时最关键的数据边界。它们决定了某个值属于临时计算、对象私有状态、地图共享状态还是更高层全局流程。

### 4.4 广播与解耦
广播在现有资料里不是边缘功能，而是结构性能力：
- UI 与地图通信
- 地图与对象协调
- 战斗事件通知
- 任务推进联动
- 多系统解耦

尤其在联机 UI 演进后，广播的重要性进一步上升，因为它成为降低 UI 与公共真值耦合的核心桥梁之一。

### 4.5 UI 系统
资料显示 UI 至少包括：
- 地图UI
- 操作UI
- 物体UI
- 当前UI 相关访问方式

更新日志表明 UI 逻辑在联机环境下经历过重要重构：从“各端模拟全部玩家 UI”转向“各玩家运行自己的 UI 逻辑”，并引出“上传并等待”“当前UI”“向当前UI发广播”等设计变化。

### 4.6 联机与同步
从 4.52.x ~ 4.54.x 相关说明可得出：
- UI 本地化执行提升了复杂界面的流畅性
- 公共数据写入具有同步代价
- UI 直接频繁修改公共数据会导致上传并等待和卡顿
- 更推荐 UI 只发请求，地图/系统集中修改真值

这使得“真值层与显示层分离”不再只是工程建议，而是和联机性能直接相关。

### 4.7 数据类型与脚本能力
引擎更新显示脚本能力并不是静态的，而是在持续进化：
- 结构体
- 公共单选值
- 向量点乘 / 叉乘
- 数字转文本 / 对数
- 声音实例
- 调试调用栈

这说明创游世界并不只是“给新手玩的简单积木”，而是在慢慢提高可表达能力。

## 5. 当前已确认的高价值工程结论

### 5.1 真值与显示必须分离
这是当前资料库反复出现、且被多个专题共同支持的核心规律：
- UI 负责显示和输入
- 地图 / 系统 / 对象层负责真实状态
- 不要让 UI 成为玩法真值的唯一来源

### 5.2 项目越大，越需要四层结构
最稳定的项目结构通常至少包括：
- 对象执行层
- 地图共享层
- 系统流程层
- UI 显示层

### 5.3 广播适合传事件，不适合替代状态存储
广播更适合作为事件化连接器，而不是到处塞隐式流程。

### 5.4 OCR 要做成工程，不只是识字
现有资料已经证明：
- 只有 OCR 文本不够
- 还要有映射表、状态标签、推进清单和总表
- 否则后续很容易漏号、重复做、难追溯

## 6. 当前发现的错误点与已修复问题

### 6.1 已发现并修复
- OCR 总览与 OCR 总表的最后更新日期异常写成了 2026，已修正为 2025
- 部分深度专题头部完整度状态写成“已整理”，但总索引中按深度整理维护，已统一修正
- 总索引缺少清晰的项目型专题推荐入口、工程维护入口和建议阅读顺序，已补齐
- 多篇旧专题缺少对新建项目型文档和工程规范文档的回链，已补强

### 6.2 仍需持续注意
- 新增文档后，旧专题的反向链接容易漏补
- 文档头字段长期维护后容易出现不一致
- OCR 工程文档中的统计、判断和索引入口需要同步更新，避免只改其中一份

## 7. 当前最值得优化的点

### 7.1 结构层优化
- 持续增强总索引的聚合能力
- 让旧专题主动回链新专题与工程文档
- 让阅读路径更清晰，减少“有文档但不知道先看什么”

### 7.2 内容层优化
- 继续补项目型文章：状态机案例、存档兼容策略
- 继续增强任务系统、交互系统等新建专题的案例密度与证据回链
- 继续补版本差异文档：数据类型演进、联机能力演进、调试能力演进
- 继续把“概念文档”提升成“模式文档”

### 7.3 OCR 工程层优化
- 给更多截图编号补状态标签
- 给三类 OCR 文档补更明确的已完成号段 / 未完成号段
- 加强 OCR 条目到专题文档的反向映射

### 7.4 AI/RAG 适配优化
- 继续统一文档头字段
- 继续统一术语与标签
- 保证单节语义集中，便于切块
- 逐步区分“事实 / 归纳 / 推测 / 待验证”
