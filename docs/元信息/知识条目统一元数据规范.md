# 知识条目统一元数据规范

[[toc]]

## 1. 文档目的

本规范用于统一 `创游世界资料汇总` 知识库中的条目结构，让后续新增文档、OCR 摘录、专题研究、版本更新记录都能使用一套相近字段，方便：

- AI 检索
- RAG 向量化
- 主题筛选
- 版本对比
- 证据追踪
- 后续人工维护

它不是要求所有旧文档立刻完全重写，而是作为今后新增/修订时的统一模板。

---

## 2. 最小元数据字段

建议每篇知识文档至少补齐以下字段：

```md
- 分类：教程 / 脚本 / 引擎更新 / 社区分析 / OCR归档 / 维护文档
- 子系统：素材 / 组件 / UI / 广播 / 地图 / 系统 / 音频 / 联机 / 调试 / 数据类型 ...
- 主题名称：文档主标题
- 关键词标签：若干关键词
- 来源类型：官方教程 / 官方更新 / 脚本界面截图 / 社区资料 / 视频主题归纳
- 证据等级：官方说明 / 截图直接证据 / 多来源交叉归纳 / 社区推测 / 待验证
- 完整度状态：草稿 / 已整理 / 深度整理 / 持续扩展中 / 近完整
- 来源文件：原始文档或 OCR 文档路径
- 来源截图编号：可选，多张时用编号列表
- 版本号：若适用
- 最后更新：日期
```

---

## 3. 推荐扩展字段

对于重要专题，建议进一步补充：

```md
- 核心结论
- 功能说明
- 限制与注意事项
- 常见误区
- 常见问题
- 关联文档
- 适合查询的问题类型
- 是否需要复核：是 / 否
- 备注
```

---

## 4. 证据等级标准

为避免“猜测”和“确定事实”混在一起，建议统一使用以下等级：

### A. 官方说明
适用情况：
- 直接来自官方教程文本
- 直接来自官方引擎更新说明
- 文字意义清晰，结论明确

可信度：最高

### B. 截图直接证据
适用情况：
- 截图中可以直接看出 UI、字段、组件、选项、接口名称
- 虽然未必有完整官方解释，但界面本身可直接证明其存在

可信度：高

### C. 多来源交叉归纳
适用情况：
- 来自多个官方截图 / 教程 / 更新内容的综合总结
- 结论不是单句原文，但有较强证据支持

可信度：中高

### D. 社区推测
适用情况：
- 来自他人经验、观察、猜测、逆向理解
- 尚无充分官方材料直接确认

可信度：中低

### E. 待验证
适用情况：
- OCR 不清
- 页面信息残缺
- 只有片段线索
- 需要后续补图或实测

可信度：最低，但仍可保留为线索

## 5. 完整度状态标准

### 草稿
- 只有初步内容
- 尚未成体系

### 已整理
- 已有明确主题和结构
- 可用于普通查询

### 深度整理
- 有较完整结构
- 有交叉分析、注意事项、关联说明
- 适合 AI 深问答

### 持续扩展中
- 已有骨架
- 还在不断补证据与新条目

### 近完整
- 主体内容基本齐备
- 剩余主要是边角补证与细节修正

## 7. OCR 文档推荐附加字段

对于 OCR 归档类文档，建议在每条记录旁尽量补：

- 图片编号
- 主题归属
- 是否有效文本
- 是否重复页
- 是否待复核
- 人工纠错说明
- 对应专题文档

例如：

```md
### 图片 110140
- 主题归属：组件定义
- 是否有效文本：是
- 是否重复页：否
- 是否待复核：否
- 对应专题文档：docs/脚本系统/专题研究/自定义组件深度解析.md
```

## 10. 维护策略建议

### 10.1 旧文档不强制全部重写
优先做法：
- 新文档直接按规范写
- 旧文档在下次修改时顺手补字段

### 10.2 优先给高价值文档补元数据
优先补这些：
- 主题索引文档
- 深度整理文档
- OCR 主归档文档
- B站视频清单

### 10.3 OCR 与专题文档要建立反向链接
理想状态：
- 专题文档能指回 OCR 证据
- OCR 记录能指向所属专题

这样以后做问答或校验时非常方便。
