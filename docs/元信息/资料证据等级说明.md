# 资料证据等级说明

为了让资料库中的内容更清晰、更可信、更方便后续维护，本资料库会逐步为重要内容标记资料来源与证据等级。

这样做的目的不是让文档变复杂，而是为了让读者知道：

- 哪些内容来自原始截图或 OCR 资料
- 哪些内容是人工整理后的结论
- 哪些内容已经比较可靠
- 哪些内容还需要后续验证
- 哪些内容适合作为学习参考，而不是最终结论

## 为什么需要证据等级？

创游世界相关资料来源比较分散，可能包含：

- 游戏内截图
- OCR 识别文本
- 官方教程内容
- 玩家经验总结
- 项目实践记录
- 人工归纳分析
- 待验证推测

如果不区分来源，读者很难判断某个结论到底有多可靠。

所以本资料库采用证据等级，让资料状态更加透明。

## 证据等级总览

| 等级 | 名称 | 含义 | 可信度 |
|---|---|---|---|
| E1 | 原始证据 | 来自截图、界面、OCR、官方内容或原始记录 | 高 |
| E2 | 整理证据 | 基于多个原始资料进行整理、分类和归纳 | 较高 |
| E3 | 研究结论 | 基于已有资料进行人工分析、总结和解释 | 中高 |
| E4 | 待验证内容 | 暂时缺少足够证据，需要后续继续验证 | 待确认 |

## E1：原始证据

E1 是资料库中最基础、最重要的证据层。

常见来源包括：

- 游戏内截图
- 创游世界界面内容
- OCR 原始识别文本
- 官方教程页面
- 原始视频截图
- 未经过深度改写的资料记录

适合用途：

- 作为资料来源
- 作为结论依据
- 作为 OCR 整理基础
- 作为后续人工校对依据

示例：

```txt
某张截图中出现了"广播消息"相关积木。
→ 这条资料属于 E1，因为它直接来自游戏内截图。
```

## E2：整理证据

E2 是基于多个 E1 资料整理、归纳、分类后形成的证据层。

常见来源包括：

- 多个截图合并整理的 OCR 文档
- 按主题分类后的脚本界面说明
- 跨教程整合后的入门路线
- 经过人工结构化但未添加新结论的资料

适合用途：

- 作为教程类文档的正文
- 作为入门路线的参考资料
- 作为后续研究的事实基础

示例：

```txt
"广播"是创游世界脚本中的一个独立积木大类，下含发送广播、接收广播、广播参数等多个积木。
→ 这条资料属于 E2，因为它从多个教程截图中归纳总结得出。
```

## E3：研究结论

E3 是基于 E1 和 E2 资料进行进一步分析、推理、对比、总结后形成的结论层。

常见来源包括：

- 综合多份资料的研究专题
- 跨页面分析后的设计建议
- 对机制边界与适用范围的推论
- 来自维护者经验的整理性观察

适合用途：

- 作为专题研究类文档的核心结论
- 作为项目设计建议的支撑
- 作为后续版本演进的对照基线

示例：

```txt
"建议把广播命名按 模块_动作_目标 三段式组织，可显著降低多人协作时的事件冲突。"
→ 这条资料属于 E3，因为它在多个 E2 整理结论之上加入了研究性建议。
```

## E4：待验证内容

E4 表示目前缺少足够稳定证据，需要继续补充或后续核实的资料。

常见来源包括：

- 单次截图或单一玩家陈述
- 缺少官方教程对应的猜测
- 引擎版本之间可能存在差异的描述
- 暂时无法在创游世界环境中复现的现象

处理方式：

- 在文档中显式标注 [E4 待验证] 或"待验证"
- 尽量不作为项目设计的硬性依据
- 等新证据进入后升级为 E1 / E2 / E3

示例：

```txt
"在某些版本中，广播参数最多可携带 5 个槽位。"
→ 这条资料属于 E4，缺少跨版本稳定证据，需要在更多版本中验证。
```

## 证据等级使用建议

| 场景 | 推荐最低等级 | 说明 |
|---|---|---|
| 入门教程正文 | E2 | 应基于多个原始资料整理 |
| 项目设计建议 | E3 | 应基于整理证据 + 研究分析 |
| 引用具体 API 行为 | E1 | 必须有原始截图或官方说明 |
| 新手路线推荐 | E2 | 优先使用已被多源验证的内容 |
| 引擎版本差异 | E1 | 需要明确的版本截图支持 |

## 维护者建议

- 升级证据等级时，尽量保留原始资料路径或编号。
- 降低证据等级时，优先判断是否资料失效或环境变化。
- 在 frontmatter 的 `evidence:` 字段中标记当前文档的主要证据组合。
- 长期维护的文档建议每年复核一次证据等级。
