本表用于把知识库中的重点文档按“成熟度、证据、关联情况、下一步动作”统一盘点，避免后续扩写时重复劳动，或者只加内容不修结构。

## 2. 状态字段说明

- 完整度：草稿 / 已整理 / 深度整理 / 持续扩展中 / 近完整
- 来源证据：是否已有官方截图、OCR、更新说明或交叉来源支撑
- 索引接入：是否已在 `docs/知识库总索引.md` 中挂入口
- 建议动作：下一步最值得做的维护项

## 4. 当前明显缺口

### 4.1 项目型文章仍有继续扩展空间
当前已经补齐“项目模板、广播驱动实战、格子 UI 模式、动作状态机、存档与云变量”等关键入口，但还可以继续往更细的任务系统、交互系统、状态机案例、存档兼容策略方向扩展。

### 4.2 工程规范文档刚起步
术语表、标签体系、状态总表已经建立入口，但仍需与旧文档形成更多反向链接，否则规范层会变成孤岛。

### 4.3 OCR 仍未逐图完整
虽然已建立总表、推进清单、映射表，但主体仍是“骨架性高价值覆盖”，尚未达到逐页全量可追溯。

---

## 5. 下一轮维护优先级建议

1. 为新补齐的项目型专题持续增加双向链接、案例和反例
2. 为现有高价值专题补“关联阅读 / 来源证据 / 适合查询”区块
3. 继续把 OCR 映射表按编号簇推进到更高完成度
4. 新增任务系统、交互系统、存档兼容与广播命名案例专题
5. 定期复查总索引与状态总表，避免新增文档后入口遗漏
6. 定期复查文档头部字段，避免日期、完整度状态、来源文件出现不一致
