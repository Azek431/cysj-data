# 创游地图与对象结构猜想

本文件根据 `资料/其他用户给的解析.txt` 中关于地图层级、图层、地块、镜头、对象组织方式的内容拆分整理，作为社区结构观察专题。

> 说明：内容为社区研究线索，不代表官方正式实现说明。

## 1. 已给出的结构示意

原文给出地图结构示意：

```text
当前地图
┗背景
┗自定义层级
    ┗图层1
        ┗未命名
            ┗（用来管理地块的）
        ┗（这是物体）
        ┗（这是物体）
         ……
    ┗（其他层级）
┗镜头
```

## 2. 从这个示意能看出什么

至少能看出地图不是“一个平面画布”，而是存在明显层次：
- 顶层有当前地图
- 地图下有背景
- 有自定义层级
- 层级下有图层
- 图层下又可能包含地块管理节点与普通物体节点
- 还有镜头对象

这和许多游戏编辑器里的“场景树/节点树”概念高度相似。

## 3. 地块与普通物体可能不是同一类节点

原文专门把某个“未命名”节点标为：
- 用来管理地块的

同时另外一些节点则被描述为：
- 这是物体

### 这意味着
地块虽然也属于地图内容，但在结构上可能是“集中管理”的，而不是完全与普通物体等价。

### 对理解编辑器很重要
这可以解释为什么：
- 地块系统常常有专用编辑方式
- 地块有特殊属性，如阻挡、摩擦、可摧毁
- 地块可能在渲染、碰撞和编辑逻辑上和普通物体不同

## 4. 镜头被视为独立节点的意义

原文结构里单独列出：
- 镜头

### 这说明
镜头很可能不是某个普通物体属性，而是地图结构中的一个独立控制对象。

### 对脚本层的启发
如果镜头是独立节点，那么很多镜头脚本可能意味着：
- 不是改物体属性
- 而是在操作地图级视觉控制对象

这与后续版本更新里修复“镜头跟踪速度受地图运行速度影响”等问题也可以互相印证。

## 5. “当前地图”和“地图物体”耦合的猜测

原文还提到一个很关键的观察：
- 地图物体本身和当前地图居然是共用一个对象

### 如果这个观察成立，意味着什么
- 地图级 API 和某些物体级 API 的底层封装可能耦合很深
- “地图”未必是一个完全独立的数据抽象层
- 有些脚本里看似不同的访问入口，底层可能指向相近对象模型

### 为什么这会带来问题
一旦抽象边界不清晰，就容易出现：
- 某些行为只在特定上下文下成立
- 某些参数传入后静默失败
- 某些对象接口看似通用，实则只适用于部分场景

## 6. 与节点树功能的互证

结合引擎更新中的“支持以节点树形式查看子物体并支持调整顺序和父子关系”，可以发现社区观察与官方更新之间存在可互证点：
- 地图/物体系统确实很可能建立在树状结构上
- 子物体不是简单标签，而是有明确父子关系
- 顺序与层级可能直接影响表现或逻辑

这说明地图结构研究不只是纯猜想，而是确实能从后续功能里看到一些旁证。

## 7. 可继续验证的问题

未来可以围绕这些问题继续做实验：
- 地块节点和普通物体节点在属性面板中有什么差异？
- 镜头对象能否像普通物体一样被脚本广泛访问？
- 地图广播的接收者层级是什么？
- 地图属性、系统属性、物体属性之间的同步边界在哪里？
- 子物体生成后在节点树里处于什么位置？

这个专题适合回答一类“结构性问题”：
