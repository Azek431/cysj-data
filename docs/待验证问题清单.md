## 1. 目的

本文件是全库级待验证问题入口。

它与 `docs/社区分析/待验证问题清单.md` 的区别是：
- 社区分析那份更偏“社区研究视角”
- 本文件更偏“整个资料库的证据治理与修复优先级”

## 3. P1：高价值机制待验证问题

### 3.1 玩家变量是否应独立建模为“第五层作用域”
- `[高可信推断]` 现有文档多按“局部 / 自身 / 地图 / 系统”四层整理
- `[待验证]` 但更新记录中已出现玩家变量数量提升等线索，说明它可能值得单独建模

### 3.2 UI、地图属性、系统属性在联机同步中的边界差异
- `[高可信推断]` UI 本地化执行、公共数据同步等待这条线已经较清晰
- `[待验证]` 但不同层级数据在联机中的精确行为边界仍需更多直接证据

### 3.3 云变量与普通运行态数据的最小推荐边界
- `[高可信推断]` 当前已有“不要滥用云变量”的工程建议
- `[待验证]` 仍需更多直接来源页来支持“何时该用 / 何时不该用”

### 3.4 广播与自定义指令在大型项目中的职责边界
- `[高可信推断]` 广播更适合事件，自定义指令更适合模块内部实现
- `[待验证]` 仍需更多实证页或官方示例支撑

## 4. P2：中长期研究问题

### 4.1 3.x 与 4.x 的脚本可观察性差异
- `[待验证]` 社区资料给出重要线索，但直接证据主要来自社区观察
- 需要：更多旧版本记录、旧截图、实机比对

### 4.2 地图、物体、地块管理节点的内部结构关系
- `[高可信推断]` 社区观察有启发意义
- `[待验证]` 仍不能作为官方事实写死

### 4.3 文本类型转脚本类型的失败原因
- `[高可信推断]` 当前更像“结构对象 + 标识信息 + 转义机制”共同导致
- `[待验证]` 尚缺更直接证据

## 5. 验证闭环要求

每个待验证问题后续应尽量按下面闭环推进：
1. 定位对应文档和截图编号
2. 补 OCR 或重新校对 OCR
3. 补专题级归纳
4. 升级为 `[已确认]` / `[高可信推断]`，或保留 `[待验证]`
5. 回写映射表、总索引、专题头部元信息
