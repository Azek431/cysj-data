## 第一步：理解核心概念（必读）

在开始操作之前，先理解这四个核心概念：

### 1. 素材 vs 物体

| 概念 | 说明 | 类比 |
|------|------|------|
| **素材** | 放在地图前的模板 | 模具 |
| **物体** | 素材放到地图上的实例 | 用模具做出的产品 |

**记住**：修改素材会影响所有物体，修改物体只影响那一个。

### 2. 组件

组件是赋予物体「能力」的东西。

**类比**：
- 角色组件 = 人的腿（能移动）
- 物理组件 = 人的身体（能碰撞）
- 动画组件 = 人的表情（能表演）

### 3. 脚本

脚本是用积木块写的行为说明书。

**基本结构**：
1. **触发时机**（何时）：当...时
2. **执行动作**（做什么）：执行...

### 4. 广播

广播是物体之间的「对讲机」，用于解耦通信。

**为什么需要广播？**
- 物体A想让物体B做某事，但A不知道B在哪里
- A发广播，B听到后自己执行

## 第二步：编辑器基本操作

### 创建第一个角色

**操作步骤**：

1. **创建素材**：在素材库点击「+」创建新素材
2. **设置外观**：导入或绘制角色的图片
3. **添加组件**：挂载「角色组件」+「物理组件」
4. **拖到地图**：把素材从素材库拖到地图上
5. **测试**：点击预览，看看角色是否能动

### 让角色动起来

**检查清单**：

- [ ] 挂载了「角色组件」
- [ ] 挂载了「物理组件」
- [ ] 添加了操作UI（虚拟摇杆或方向键）
- [ ] 组件层级关系正确

### 常见问题

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 角色不走 | 缺少物理组件 | 添加物理组件 |
| 角色穿墙 | 碰撞层级不对 | 调整碰撞层级 |
| 地图没变化 | 没应用素材更新 | 使用「应用到原素材」 |

## 第三步：脚本入门

### 脚本基本结构

```
当 [触发时机] 时
  执行 [动作1]
  执行 [动作2]
  ...
```

### 常用触发时机

| 触发时机 | 何时执行 | 入门场景 |
|----------|----------|----------|
| 初始化 | 物体创建时 | 设置初始状态 |
| 每帧 | 每帧循环 | 持续移动 |
| 碰撞开始 | 碰到其他物体 | 拾取物品、伤害判定 |
| 收到广播 | 收到指定广播 | 事件响应 |
| 手指按下 | 点击屏幕 | 按钮交互 |

### 入门示例

**场景**：玩家碰到金币时，金币消失并播放音效

**脚本写法**：
```
当 [碰撞开始] 与 [玩家] 时
  播放音效 [coin]
  销毁 [自己]
```

**避坑点**：
- 广播名称要完全一致（包括大小写）
- 变量名要有意义，避免混淆
- 循环要有等待，避免卡死

## 第四步：快速检查清单

### 角色不动？检查这些：

- [ ] 是否挂了「角色组件」？
- [ ] 是否挂了「物理组件」？
- [ ] 是否有操作UI？
- [ ] 物理碰撞层级是否正确？
- [ ] 组件顺序是否正确？

### 脚本不执行？检查这些：

- [ ] 触发时机是否正确？
- [ ] 脚本是否在正确的物体上？
- [ ] 条件判断是否满足？
- [ ] 是否有死循环导致卡死？

### 广播没效果？检查这些：

- [ ] 发送广播和接收广播的名称是否完全一致？
- [ ] 接收脚本的触发时机是否是「收到广播」？
- [ ] 发送广播的对象是否还存在？
- [ ] 接收广播的物体是否在场景中？

### 变量值丢失？检查这些：

- [ ] 是否使用了对象变量？
- [ ] 物体是否被销毁后重新创建？
- [ ] 是否需要用属性变量或全局变量？

## 第五步：记住这些关键数字

| 项目 | 限制 | 说明 |
|------|------|------|
| 背包格子 | 200格 | 最大背包容量 |

| 广播名称 | 区分大小写 | 建议统一小写+下划线 |

## 常见坑点总结

### 新手必踩的10个坑

1. **角色不走**：忘记挂物理组件
2. **广播没用**：名称写错了
3. **素材不变**：没点「应用到原素材」
4. **变量没了**：用了对象变量，对象销毁后重置
5. **循环卡死**：没有等待语句
6. **UI乱跳**：UI层级设置错误
7. **动画不动**：动画组件没正确绑定
8. **碰撞失败**：碰撞层级冲突
9. **脚本乱**：没有规划好脚本结构
10. **项目乱**：没有好的项目组织习惯

### 避坑建议

1. 养成先规划再动手的习惯
2. 善用注释标记代码逻辑
3. 变量名要有意义
4. 广播名称统一规范
5. 定期检查和整理项目
