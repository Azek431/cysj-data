# 创游世界组件系统完全指南

本指南旨在帮助所有创游世界用户——从新手到进阶开发者——系统理解组件系统的设计理念、官方组件分类、以及如何通过自定义组件实现可复用功能模块。

## 一句话摘要

组件是创游世界赋予对象"能力"的模块。理解组件分类、自定义组件的「属性 / 指令 / 触发时机」结构，是从"摆素材"升级到"做功能"的关键一步。

## 1. 什么是组件

### 1.1 组件的本质

**组件是对象的功能模块，决定这个对象"能做什么"。**

贴图决定"看起来像什么"，组件决定"实际上能做什么"。不给物体挂组件，它就只是一个静态图片。

打个比方：
- 一个箱子贴图，如果没挂交互或物理组件，它可能只是个摆设
- 一个按钮贴图，如果挂了可互动、开关、广播等组件，它才能成为机关的一部分

### 1.2 组件vs素材的关系

| 区别 | 素材 | 组件 |
|------|------|------|
| 本质 | 模板/资源 | 能力模块 |
| 作用 | 提供外观和初始配置 | 赋予物体具体功能 |
| 修改影响 | 修改素材不一定影响已有地图物体 | 挂载到物体上决定该物体能力 |

> ⚠️ **重要**：修改素材模板不会自动更新地图里已有的物体实例。如果需要同步，需要使用"应用到原素材"功能。

## 2. 官方组件六大分类

从组件添加界面截图可确认，创游世界的组件系统包含以下六大分类：

### 2.1 通用类组件

通用组件是大多数物体都可能用到的基础能力，包括：

| 组件 | 功能说明 |
|------|----------|
| 物理 | 让物体具有物理属性，可以移动、受力、碰撞 |
| 可互动 | 让物体可以被玩家接近并触发交互 |
| 开关 | 让物体具有开/关两种状态 |
| 阻挡通行 | 让物体阻挡玩家或其他物体移动 |
| 等级 | 记录物体的等级数值 |
| 告示牌 | 显示文字提示信息 |
| 物体UI | 让物体可以绑定一个UI界面 |

### 2.2 战斗类组件

战斗类组件负责游戏战斗相关的能力：

| 组件 | 功能说明 |
|------|----------|
| 生命 | 让物体具有血量，可以受伤和死亡 |
| 伤害 | 定义物体造成的伤害数值和类型 |
| 武器槽 | 让物体可以装备武器进行攻击 |
| 子弹 | 让物体可以发射子弹进行远程攻击 |

### 2.3 装置类组件

装置类组件主要用于机关、机关门、机关地板等互动场景：

| 组件 | 功能说明 |
|------|----------|
| 机关 | 用于设计机关逻辑 |
| 机关门 | 可控制的门对象 |
| 机关地板 | 压力板等机关触发器 |

### 2.4 显示类组件

显示类组件负责视觉效果：

| 组件 | 功能说明 |
|------|----------|
| 粒子特效 | 让物体产生粒子效果 |
| 动效 | 让物体播放动态效果 |

### 2.5 交互类组件

交互类组件定义物体与玩家的交互方式：

| 组件 | 功能说明 |
|------|----------|
| 移动摇杆 | 提供虚拟摇杆控制移动 |
| 技能摇杆 | 提供虚拟摇杆控制技能释放 |
| 互动按钮 | 玩家接近时显示的交互提示按钮 |
| 通用摇杆 | 通用方向控制 |
| 输入框 | 文本输入组件 |

### 2.6 自定义组件

自定义组件是创作者自己定义的能力模块，可以通过脚本编辑器添加属性、指令和触发时机，是扩展引擎能力的主要方式。

## 3. 组件添加界面解析

### 3.1 如何添加组件

1. 在地图中选中目标物体
2. 进入对象属性面板
3. 找到"添加组件"入口
4. 选择需要的组件类型

### 3.2 组件添加界面结构

从截图观察，组件添加界面包含：
- 组件分类标签页（通用/战斗/装置/显示/交互/自定义）
- 组件搜索/筛选功能
- 组件详细说明面板

## 4. 自定义组件深度解析

### 4.1 自定义组件的三大元素

自定义组件编辑器支持三类核心元素：

#### 属性（Properties）

属性用于存储组件的状态数据，例如：
- 数字属性：存储数值状态
- 文本属性：存储字符串状态

#### 指令（Functions）

指令是组件对外提供的行为入口，例如：
- `当执行"指令1"时` → 定义该指令的具体行为
- 可被其他脚本或组件调用

#### 触发时机（Triggers）

触发时机是组件响应特定事件的机会，例如：
- `当受到伤害时`
- `当对象被创建时`
- `当广播被触发时`

### 4.2 自定义组件编辑界面

从截图可识别到的界面元素：
```
组件名：我的组件1

属性：
- 数字1
- 文本1

操作按钮：
- +添加属性
- +添加指令
- +添加触发时机

底部功能：
- 数据
- 保存
- 试玩
```

### 4.3 自定义组件的价值

自定义组件的本质是"带状态与行为的可复用模块"，它的价值在于：

1. **复用**：同一个组件可以挂载到多个物体上
2. **统一接口**：多个对象共享同一行为协议
3. **降低重复**：不需要在每个物体上重复写相同逻辑
4. **封装**：把能力封装成独立模块，便于维护

## 5. 组件与脚本的配合

### 5.1 脚本可以挂在哪里

在创游世界中，脚本可以挂在多个层级：

```
脚本层级结构：
├─ 对象脚本（绑定到特定物体）
├─ 组件相关脚本（通过自定义组件定义）
├─ 地图脚本（当前地图范围内生效）
├─ 系统脚本（全局范围生效）
└─ UI侧逻辑（界面相关处理）
```

### 5.2 脚本访问组件的方式

脚本通过组件提供的接口与组件交互：

1. **读取属性**：获取组件当前状态
2. **调用指令**：触发组件的特定行为
3. **响应触发**：在特定事件发生时执行逻辑

### 5.3 组件能力分层

组件的能力可以分为三个层次：

| 层次 | 说明 | 示例 |
|------|------|------|
| 基础能力 | 组件自带的基础功能 | 物理组件提供碰撞和移动 |
| 可配置参数 | 可以调整的数值 | 伤害值、攻击速度 |
| 脚本扩展 | 通过脚本进一步扩展 | 自定义逻辑、复杂行为 |

## 7. 组件使用常见误区

### 误区1：以为贴图自带功能

> 实际上：没有挂载对应组件，贴图只是一个静态图片，不会自动具有任何功能。

### 误区2：以为一个组件可以做所有事

> 实际上：组件是功能模块，需要根据需求组合使用。例如战斗可能需要生命组件+武器槽组件+子弹组件配合。

### 误区3：修改素材后地图物体自动更新

> 实际上：地图里的物体是实例，修改素材模板不会自动更新已摆放的物体。需要使用"应用到原素材"或重新摆放。

### 误区4：自定义组件用得越多越好

> 实际上：合理的组件设计应该保持"高内聚、低耦合"。不是所有东西都需要做成自定义组件。

## 8. 组件与对象能力组合思维

创游世界的核心思维方式是"**对象 = 基础实体，组件 = 能力组合，脚本 = 行为编排**"。

做功能时，应该先判断：
1. 这个功能属于哪个对象？
2. 这个对象需要哪些组件？
3. 脚本应该绑定在哪个层级、响应什么触发时机？
