# UI系统与切换机制解析

本文基于官方教程截图中关于 UI 切换、地图 UI、操作 UI、物体 UI 的说明，整理创游世界 UI 系统的结构与常见误区。

## 1. UI 的分类结构

从教程截图可确认，创游中的 UI 至少分为三类：
- 地图 UI
- 操作 UI
- 物体 UI

这说明“UI”并不是一个单一对象类型，而是按用途和挂载位置拆分的多个子系统。

### 结构理解
- **地图 UI**：更偏全局界面，通常跟地图或场景级逻辑联动。
- **操作 UI**：更偏输入、按钮、控制面板等玩家操作层界面。
- **物体 UI**：与某个物体绑定，属于组件式 UI 能力。

## 2. 为什么切换 UI 时会“找不到做好的 UI”

根据截图内容，常见原因不是 UI 消失，而是**指令找错了位置**。

可提炼出的规则：
- 切换不同类型的 UI，要使用对应作用域或对应入口下的指令。
- 不能把地图 UI、操作 UI、物体 UI 的切换方式混用。
- 尤其是物体 UI，因为它本质上带有“组件属性”，不是纯全局对象，所以调用路径不同。

## 3. 物体 UI 的本质：组件化 UI

教程截图明确提到：
- 物体 UI 是一个组件
- 因此需要先给物体挂这个组件，才能使用相应指令

这意味着：
- 物体 UI 不是自动存在的
- 也不是所有物体天生可切换物体 UI
- 必须先完成“组件挂载 -> 获得能力 -> 再调用切换/显示相关指令”这一链路

这与创游整体设计高度一致：
- 组件决定能力
- 脚本决定行为
- UI 也遵循这一能力授权模型

## 4. UI 设计上的分层思想

结合引擎更新说明，可以把创游 UI 理解为三层：

### 4.1 逻辑触发层
例如：
- 玩家事件
- 地图广播
- 系统事件

### 4.2 UI 承载层
也就是：
- 当前 UI
- 地图 UI
- 物体 UI
- 操作 UI

### 4.3 UI 内部处理层
在较新的 UI 逻辑里，官方推荐：
- 外部不要直接跨层操作 UI 内细节
- 更推荐“向当前 UI 发广播”
- 再由 UI 自己处理内部逻辑

这说明 UI 正在从“被外部强控的显示对象”转向“具备自身脚本自治能力的界面对象”。

## 5. 与联机 UI 更新的关系

在引擎更新说明里，`玩家.当前UI` 被弃用并改为 `当前UI`，同时推荐：
- 执行“玩家.向当前UI发广播”
- 让 UI 收到广播后自行处理

这与教程里的 UI 分类并不冲突，反而形成互证：
- UI 有明确类型与边界
- UI 逻辑更适合在 UI 内部执行
- 外部系统负责通知，不负责直接深层操控

## 6. 常见误区

### 误区 1：做好 UI 后所有地方都能直接切换
不对。不同 UI 类型对应的指令位置可能不同。

### 误区 2：物体 UI 和地图 UI 没区别
不对。物体 UI 是组件化能力，需要挂载才能使用。

### 误区 3：地图脚本应该直接修改 UI 细节
在新逻辑下不推荐。更适合用广播通知 UI 自己更新。

## 7. 实战建议

### 如果你要做全局界面
优先考虑：
- 地图 UI
- 操作 UI

### 如果你要做某个物体头顶血条、提示框、交互标记
优先考虑：
- 物体 UI 组件

### 如果你在联机模式下写 UI 动画或复杂界面
优先采用：
- 外部广播通知
- UI 内脚本处理

避免：
- 频繁在地图脚本里直接操作 UI 公共数据
- 让多条同步上传脚本串联
