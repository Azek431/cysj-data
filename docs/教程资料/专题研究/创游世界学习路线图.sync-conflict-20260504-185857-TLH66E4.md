# 创游世界学习路线图

本专题把当前知识库中已经整理出的官方教程、脚本界面、引擎更新与 B 站视频资源串成一条更适合学习与检索的路线，目标不是重复单页教程，而是回答一个更实际的问题：**如果我要系统学会创游世界，应该先学什么、再学什么、每一步解决什么问题。**

## 1. 学习目标拆分

创游世界的学习并不是单一技能，而是至少包含以下几层：
- 认识编辑器里的对象、素材、组件与地图
- 学会把素材摆进地图，并理解“素材”和“地图里的物体”不是一回事
- 学会给物体挂组件，让它具备功能
- 学会用脚本处理交互、战斗、UI、流程与数据
- 学会把多个系统接成完整玩法
- 学会根据版本更新调整旧工程做法

换句话说，真正的学习路径应该是：
**素材认知 → 组件认知 → 脚本认知 → UI 与广播 → 系统搭建 → 版本兼容与优化。**

---

## 2. 第一阶段：先建立“编辑器世界观”

### 这一阶段要弄懂什么
- 什么是素材
- 什么是物体
- 什么是组件
- 什么是地图层级
- 素材怎么移动、复制、整理到文件夹

### 为什么必须先学这个
很多新手一开始最容易混淆：
- 为什么我改了素材，地图里的东西没变化？
- 为什么有的东西能加组件，有的不能？
- 为什么同一张贴图放到地图里以后，行为和素材库里不一样？

这些问题本质上都属于“素材系统认知没建立好”。

### 对应知识库文档
- `docs/tutorials/官方教程知识索引.md`
- `docs/tutorials/topics/素材系统与组件挂载解析.md`
- `docs/tutorials/topics/素材实例化与地图物体关系解析.md`
- `docs/ocr-text/官方教程截图转文本索引.md`

### 学完后应该能做到
- 能区分素材与地图物体
- 知道组件是功能来源，而不是贴图本身自带
- 知道复制素材、移动素材、贴图文件夹这些操作属于资源管理，而不是玩法逻辑

## 3. 第二阶段：建立“组件决定能力”的认知

### 这一阶段要弄懂什么
- 组件分类为什么这么重要
- 通用 / 战斗 / 装置 / 显示 / 交互 / 自定义分别解决什么问题
- 官方内置素材为什么往往“拿来就能用”
- 自制素材为什么要自己挂组件

### 核心理解
在创游世界里，**组件比贴图更接近真正的功能单元**。
贴图决定“看起来像什么”，组件决定“实际上能做什么”。

例如：
- 一个箱子贴图，如果没挂交互或物理组件，它可能只是个摆设
- 一个按钮贴图，如果挂了可互动、开关、广播等组件，它才真正成为机关的一部分

### 对应知识库文档
- `docs/scripts/脚本界面与积木知识索引.md`
- `docs/scripts/topics/组件添加界面深度解析.md`
- `docs/scripts/topics/脚本组件体系与能力分层深度研究.md`
- `docs/tutorials/topics/素材系统与组件挂载解析.md`

### 学完后应该能做到
- 看到一个玩法需求时，先想到要挂什么组件
- 不再把“素材类别”和“玩法能力”混成一件事
- 开始形成“对象能力组合”的思维方式

## 4. 第三阶段：进入脚本系统

### 这一阶段要弄懂什么
- 自定义组件是什么
- 属性、指令、触发时机分别扮演什么角色
- 局部变量 / 自身属性 / 地图属性 / 系统属性的区别
- 常见积木块能控制什么

### 核心理解
脚本系统不是孤立存在的，它通常挂在组件和对象上执行。
因此更准确地说，创游世界的脚本学习不是“学代码”，而是“学对象、组件、事件和数据如何组合起来”。

### 建议先掌握的最小闭环
1. 给对象加一个自定义组件
2. 定义一个属性存状态
3. 定义一个指令作为外部调用入口
4. 在触发时机里修改属性
5. 用广播或其他对象调用该指令

只要这个闭环能通，你就已经跨过“看教程”和“会做功能”之间最大的门槛。

### 对应知识库文档
- `docs/scripts/topics/自定义组件深度解析.md`
- `docs/scripts/topics/脚本作用域与数据流深度研究.md`
- `docs/scripts/topics/系统级脚本能力解析.md`
- `docs/ocr-text/基础写脚本界面截图转文本.md`

### 学完后应该能做到
- 理解脚本的执行入口不是只有一个
- 能分清临时变量、对象状态、地图状态、系统状态
- 能写简单的交互逻辑、流程逻辑和对象行为逻辑

## 5. 第四阶段：学会用广播和 UI 解耦

### 这一阶段要弄懂什么
- 广播为什么重要
- 为什么地图逻辑和 UI 逻辑不应该乱写在一起
- 地图 UI、操作 UI、物体 UI 分别适合干什么
- 联机环境下 UI 为什么要注意“当前 UI”的访问方式

### 核心理解
广播的真正价值，不是“能发消息”，而是：
**让不同对象、不同层级、不同系统之间尽量不要硬绑死。**

而 UI 的真正难点也不是“显示东西”，而是：
**如何把地图状态、玩家状态、系统状态正确地同步到界面。**

### 对应知识库文档
- `docs/tutorials/topics/广播机制深度解析.md`
- `docs/tutorials/topics/UI系统与切换机制解析.md`
- `docs/engine-updates/topics/联机UI演进专题.md`

### 学完后应该能做到
- 用广播触发 UI 更新，而不是到处直接改界面
- 知道什么信息该放地图层，什么信息该放 UI 层
- 能看懂旧教程和新版本在 UI 调用方式上的差别

---

## 6. 第五阶段：开始搭“完整玩法系统”

### 这一阶段要做什么
把前面学到的素材、组件、脚本、UI、广播真正组合起来，做完整系统。

### 最适合练手的系统
- 血条 / 生命系统
- 货币 / 货币条系统
- 拾取与背包雏形
- 武器伤害系统
- 按钮 / 开关 / 门机关联动
- 签到 / 抽奖 / 奖励领取

### 这些系统为什么适合练手
因为它们往往会同时覆盖：
- 对象状态
- UI 展示
- 事件触发
- 数据读写
- 多对象协作

也就是说，一个功能做通了，通常就不是只学会一个按钮，而是学会一整套系统思维。

### 对应知识库来源
- 官方教程 OCR 中的生命、货币、武器、拾取参数等页面
- 脚本界面 OCR 中的系统级脚本与动作块
- B 站资源清单中的血条、翻滚、背包、抽奖、签到等视频主题

## 7. 第六阶段：学会看版本更新，避免学成过时做法

### 为什么必须学这个
创游世界并不是静止的，UI、数据类型、脚本能力、联机逻辑、声音系统、调试方式都在持续更新。
如果只看旧视频，容易学到：
- 已不推荐的 UI 写法
- 老的兼容逻辑
- 旧版本 Bug 绕法
- 已被新版本替代的工作流

### 应重点关注的版本主题
- `4.54.0`：结构体、单选值、数学能力、联机 UI 调整
- `4.52.x`：当前 UI、上传并等待、联机 UI 本地化
- `4.43.24`：BGM / UI 类型、当前 UI 元素属性
- `4.40.17`：逐行 Debug 与调用栈
- `4.40.5`：多人同时编辑工程

### 对应知识库文档
- `docs/engine-updates/引擎更新知识索引.md`
- `docs/engine-updates/topics/4.54.0 数据类型与脚本能力升级解析.md`
- `docs/engine-updates/topics/联机UI演进专题.md`
- `docs/ocr-text/引擎更新截图转文本.md`

### 学完后应该能做到
- 知道某个教程是不是老版本做法
- 能根据版本变化调整工程架构
- 能更理性地判断“这是引擎限制，还是教程过时”

## 8. 推荐的实际学习顺序

如果按最省力的路线，建议顺序如下：

1. 先看“什么是素材 / 什么是组件 / 地图层级”
2. 再看“组件分类和组件挂载”
3. 再学“自定义组件、属性、指令、触发时机”
4. 再学“作用域和数据流”
5. 再学“广播和 UI”
6. 再做“生命 / 货币 / 拾取 / 门机关”这些小系统
7. 最后把引擎更新补进自己的认知模型里

这是因为：
- 没搞懂素材和组件，脚本会学得很虚
- 没搞懂作用域，脚本很容易写乱
- 没搞懂广播和 UI，系统一复杂就会缠死
- 不看版本更新，越学越容易踩旧坑
