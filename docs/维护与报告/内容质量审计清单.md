# 内容质量审计清单

这个页面用于记录资料库中的内容质量问题，帮助后续持续优化。

它不是普通用户必读页面，而是维护者用来判断：

- 哪些文档需要合并
- 哪些文档需要补证据
- 哪些文档需要补 frontmatter
- 哪些文档需要改成站内链接
- 哪些文档需要改表格格式
- 哪些文档需要补“最小可做版本”
- 哪些导航入口需要更新

## 当前优先级

| 优先级 | 类型 | 说明 |
|---|---|---|
| P0 | 仓库清理 | 移除误提交的备份目录、构建产物和临时文件 |
| P1 | 入口整理 | 保证首页、按问题查资料、知识库总导航、分类导航层级清晰 |
| P2 | 链接规范 | 把文档中的 `docs/...md` 仓库路径逐步改为 VitePress 站内链接 |
| P3 | 证据回链 | 给 E3 研究结论补充 OCR、截图或原始资料来源 |
| P4 | 内容合并 | 合并重复报告、重复指南和版本过多的阶段性文档 |
| P5 | 教程增强 | 给实战文档补“最小可做版本、变量设计、广播设计、常见错误” |

## 表格格式检查

需要重点检查这些类型的内容：

- `系统 文档 说明`
- `误区 后果 正确做法`
- `文档 说明 适合阶段`
- `变量名 类型 作用`
- `广播名 触发方 接收方 作用`

如果显示成普通文本，应改为标准 Markdown 表格。

## 链接规范

推荐使用 VitePress 站内链接：

[新手阅读路线](/总索引与导航/新手阅读路线)

尽量避免在普通用户阅读页大量使用：

`docs/总索引与导航/新手阅读路线.md`

仓库路径可以保留在 README 或维护文档中，但普通用户阅读页应优先使用站内链接。

## 后续维护原则

1. 新增重要文档后，必须挂到至少一个导航入口。
2. 新增研究结论后，尽量标注证据等级。
3. 新增教程文档后，尽量补“最小可做版本”。
4. 历史报告不要直接删除，先归档、再建立当前状态页。
5. 优先优化高频入口页面，而不是平均修改所有文档。
