# 资料校对与证据规则

这份规则用于约束资料型文档的后续维护。

本站内容以资料整理、证据追溯和学习导航为核心，不把 AI 推理直接当成官方事实。

## 内容分层

后续校对时，建议把内容分成三类：

- 资料事实：来自官方教程、引擎更新、截图、OCR、可复查资料。
- 经验总结：来自实际使用、项目整理、维护观察。
- 推理模型：为了帮助理解机制而做的解释性总结。

## 写作原则

资料型内容优先使用克制表达：

- 可以写“根据现有截图和 OCR 资料，可以判断……”
- 可以写“在当前资料范围内，暂时没有看到……”
- 可以写“该结论仍需后续实测或官方资料补充……”

尽量避免没有证据的强结论：

- 必须
- 一定
- 只能
- 完全
- 永远
- 绝对
- 所有情况
- 官方明确说明

## 修改原则

发现资料和正文不一致时，优先按这个顺序处理：

1. 保留原始资料。
2. 标记正文结论的证据来源。
3. 对没有证据的强结论降级为“待验证”或“经验总结”。
4. 明确区分官方机制、OCR 资料、个人整理和 AI 推理。
5. 修改正文时尽量保留可追溯链接。

## 审计命令

深度审计：

    pnpm run docs:kb:audit

安全格式修复预览：

    pnpm run docs:style:fix:dry

安全格式修复：

    pnpm run docs:style:fix

这些命令只负责发现和修复明显结构问题，不应该替代人工资料核对。
