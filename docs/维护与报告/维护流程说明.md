# 维护流程说明

[[toc]]

## 1. 推荐维护流程

### 第一步：先判断这次维护属于哪一类
- 补导航
- 补专题正文
- 补 OCR 证据
- 修错误链接
- 修术语和分类
- 更新状态与路线图

### 第二步：先看治理文档
优先阅读：
1. `docs/维护与报告/资料规范与状态总览.md`
2. `docs/错误点与优化点汇总.md`
3. `docs/待验证问题清单.md`

### 第三步：定位改动层级
优先级建议：
1. 先修总导航和栏目导航
2. 再修高价值专题页
3. 再补 OCR 证据链
4. 最后再做细枝末节的格式统一

### 第四步：改完后必须补回链
每次新增或扩写页面，至少检查：
- 是否能从总导航进入
- 是否能从所属栏目页进入
- 是否写了关联阅读
- 是否有必要回链到 OCR / 维护页

### 第五步：更新状态
改完后应尽量同步更新：
- 当前状态
- 可信度
- 待验证项
- 仍可继续补强的部分

## 维护时最容易出的问题

- 只补正文，不补入口
- 只补入口，不补回链
- 只写结论，不写可信度
- 只做分类，不做使用说明
- 不区分“已确认”和“待验证”

## 推荐的单次维护目标

一次维护最好只聚焦一种目标，例如：
- 把一个栏目补完整
- 把 3~5 篇高价值专题补统一头部
- 把一组 OCR 证据整理成可回链结构
- 把一批错误链接和命名问题统一修掉

## 收尾检查清单

- [ ] 路径是否正确
- [ ] 标题是否明确
- [ ] 有无一句话摘要
- [ ] 有无适合对象 / 当前状态 / 可信度
- [ ] 有无关联阅读
- [ ] 是否接入栏目或总导航
