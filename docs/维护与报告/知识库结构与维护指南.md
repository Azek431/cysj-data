## 二、文档命名规范

### 文件命名原则

1. **使用中文命名**：文件名尽量使用中文，便于中国用户识别和搜索
2. **避免过长**：文件名控制在 20-50 个中文字符以内
3. **表达主题**：文件名应清晰表达文档主题
4. **避免特殊字符**：不要使用 `\ / : * ? " < > |` 等特殊字符
5. **统一格式**：使用 `-` 分隔多词，例如 `创游世界脚本入门完全指南.md`

### 示例

| 好的命名 | 不推荐的命名 | 原因 |
|----------|--------------|------|
| `创游世界脚本入门完全指南.md` | `脚本入门.md` | 主题不够明确 |
| `广播机制深度解析.md` | `broadcast.md` | 不够直观 |
| `常见问题与避坑指南.md` | `FAQ.md` | 不够中文友好 |

## 四、文档结构标准

### 推荐结构（长文档）

```markdown
# 标题

## 一句话摘要
用 1 到 3 句话说明这篇文档讲什么、解决什么问题。

## 适合谁阅读
说明适合人群。

## 你将学到什么
用列表说明读者读完能获得什么。

## 核心结论
先给重要结论，不要绕弯子。

[[toc]]

## 背景说明
解释为什么这个主题值得单独整理。

## 基础概念
用新手能理解的语言解释相关概念。

## 详细解析
结合资料库已有内容进行深入说明。

## 示例说明
提供场景、操作思路、伪代码、项目设计例子。

## 常见问题
整理读者可能会遇到的问题。

## 注意事项
标出容易误解、容易踩坑、需要验证的地方。

## 相关页面
补充站内相关文档链接或建议互链。

## 待验证问题
列出不能确定的内容。

## 后续优化方向
说明这篇文档以后还能补什么。
```

### 简洁结构（短文档/FAQ）

```markdown
# 标题

## 一句话摘要

## 核心结论

## 快速问答

## 相关页面
```

## 五、SEO 与 AI 检索优化

### 标题优化

1. 标题应包含核心关键词
2. 标题长度控制在 20-50 字符
3. 避免标题过于笼统

### Description 优化

1. 用一句话清楚说明页面价值
2. 包含核心关键词
3. 控制在 80-150 字符

### 内容优化

1. 第一屏能让读者快速知道主题
2. H2/H3 标题语义清楚
3. 重要结论短句表达
4. FAQ 有助于搜索收录
5. 相关页面形成站内互链

### 标签优化

1. tags 不要太泛
2. 每个文档 5-10 个具体标签
3. 包含主题关键词和分类关键词

## 六、如何贡献新文档

### 贡献步骤

1. **确定分类**：根据文档内容选择合适的分类目录
2. **检查命名**：使用中文命名，避免特殊字符
3. **编写 frontmatter**：包含必填字段
4. **撰写正文**：遵循文档结构标准
5. **添加相关页面链接**：与已有文档建立互链
6. **提交贡献**：通过 GitHub Pull Request 提交

### 新文档优先级

1. 新手入门文档
2. 概念解释文档
3. 脚本系统教程
4. UI 与交互教程
5. 对象与组件教程
6. 系统设计教程
7. OCR 资料整理说明
8. 引擎更新解读
9. 常见问题 FAQ
10. 项目结构模板

## 七、文档维护检查清单

在提交文档前，请检查：

- [ ] 文件名使用中文，表达主题
- [ ] frontmatter 包含必填字段
- [ ] description 用一句话说明页面价值
- [ ] tags 包含具体关键词（5-10 个）
- [ ] 标题层级清晰（H1 > H2 > H3）
- [ ] 有核心结论或摘要
- [ ] 有相关页面链接
- [ ] 证据等级标注清楚
- [ ] 待验证内容标注 `[待验证]`
- [ ] 没有编造不存在的功能或 API
- [ ] 没有把推测写成事实
- [ ] 没有把社区经验写成官方结论
